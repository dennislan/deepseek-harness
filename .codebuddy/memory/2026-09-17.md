# 2026-09-17

## dsh-mcp-plugin：单个 MCP server 挂载失败不再拖垮启动

现象：`dsh` web profile 无法启动（`plugin tree failed to load`），因为 `~/.dsh/mcp-servers.json` 里
`postgres` 的 `command` 指向已被清理的 npx 缓存路径，且该条目 `failOnStartupError: true`；
`McpManager.restore()` 里 `mountOne` 抛出 → `apply()` 拒绝 → 整个 loader entry 失败。

修复（`dsh-mcp-plugin/src/`）：
- `McpManager.restore()` 改为并发挂载且 `mountOne(spec, { fatal: false })`——单个 server 的失败被
  隔离、记入 `errors` map、logger.warn 后继续启动。
- `mountOne` 新增 `{ fatal }` 选项：`add`/`modify` 仍 fatal（用户操作要看到报错），restore 不 fatal。
- `McpServerRecord.lastError`（含 cause 链，见 `errorMessage` 展开）→ `mcp_list` 输出 `error` 字段、
  `/api/mcp/list`、客户端面板与 composer dock 红点/错误文案。
- 测试用例：`boots with a stored server whose command no longer exists, reporting it offline`。

部署方式：`dsh-mcp-plugin/scripts/deploy.sh --force`（tsc + client bundle，再拷贝到
`~/.dsh/profiles/web/node_modules/dsh-mcp-plugin/lib`）。实测 11 个测试通过。

注意：恢复时仍沿用存储的 `failOnStartupError`（true 的 server 挂不上就只报 lastError、不再重连；
false 的保留 mcp-client 重连循环）。用户侧那条 postgres 条目本身仍然是坏的，需要用
`mcp_modify` 或设置页把 command 换成可长期存在的可执行文件。
